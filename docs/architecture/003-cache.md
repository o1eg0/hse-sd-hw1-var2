# ADR-003: Стратегия кэширования внешних источников данных (Draft)

> Статус: Draft \
> Команда: 9 \
> Дата: 2025-11-20

## Контекст

Некритичные источники (config, tariffs) требуют специальных стратегий кэширования для обеспечения отказоустойчивости при недоступности внешних сервисов.

## Решение

#### Config Service

Redis кэш с TTL из `pricing_settings.config_ttl_sec` (60 секунд)

Стратегия "cache-aside": при cache miss идет запрос к внешнему сервису

Timeout запроса: 1.0 секунда

При недоступности сервиса возвращается fallback конфигурация с дефолтными значениями:

```python
Config(
    price_coeff_settings={"last_banks_increase": 1.5},
    tariff_cache_ttl_sec=600,
    offer_ttl_sec=300,
    fallback_greedy_coeff=2.0
)
```
Реализация: async/await через httpx.AsyncClient + redis.asyncio


#### Tariff Service

Redis кэш с динамическим TTL (передается из config или дефолт 600 секунд)

Стратегия "cache-aside" с быстрым фейлом

Timeout запроса: 1.0 секунда

При cache miss и недоступности upstream $\to$ HTTP 503 с сообщением `"Tariff data is stale or upstream unavailable"`

Реализация: аналогично

Важно: Нет проверки давности данных - если данные в кэше, они используются независимо от времени их добавления

## Альтернативы

- Circuit Breaker Pattern: Дополнительная сложность, но можно добавить позже для автоматического перехода в режим деградации
- Отказ от кэширования: Неприемлемо из-за требований по отказоустойчивости

## Последствия

- Предсказуемая деградация при сбоях некритичных сервисов
- Снижение нагрузки на внешние API
- Меньше задержки (кэш быстрее, чем HTTP-запрос)
