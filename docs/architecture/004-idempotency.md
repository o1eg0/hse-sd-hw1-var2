# ADR-004: Идемпотентность операций (Draft)

> Статус: Draft \
> Команда: 9 \
> Дата: 2025-11-20

## Контекст

Клиенты могут повторять запросы из-за сетевых сбоев или таймаутов. Необходимо гарантировать идемпотентность мутирующих операций (создание оффера, старт аренды, возврат).

## Решение

HTTP Headers:
- Обязательный заголовок `Idempotency-Key: <UUID>` для POST/PUT/DELETE операций
- Заголовок генерируется клиентом (UUID v4)
- При отсутствии $\to$ `HTTP 400 Bad Request`

Хранение ключей:
- Таблица `idempotency_keys` в PostgreSQL
- Scope (rental_start, offer_create, rental_return)
- Request hash (SHA256 от параметров запроса)
- Response body (сериализованный JSON ответа)
- TTL записи: 24 часа (автоочистка через pg_cron)

## Альтернативы
- Natural keys: Использовать комбинацию user_id+station_id как естественный ключ — не подходит, т.к. пользователь может создавать несколько офферов
- Без идемпотентности: Риск дублирования заказов и двойного списания

## Последствия
- Гарантия exactly-once семантики
- Защита от дублирования платежей
- Дополнительный запрос к БД на каждую мутацию (+10-20ms)
- Необходимость клиентам генерировать UUID
